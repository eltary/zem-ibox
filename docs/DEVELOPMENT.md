# Сборка и тестирование

Работайте из корня checkout в WSL/Linux. Пакет приложения: `io.zem.ibox`.
Минимальная версия ОС — Android 7.0 (API 24). Требуются Java 17, Android SDK 36 и Gradle Wrapper из проекта.
`ANDROID_HOME` или игнорируемый `local.properties` задают путь к SDK.

## Подпись

Применяется существующая внешняя конфигурация
`~/zem-android-sign/zem-signing.gradle` и `signing.properties` в том же каталоге.
Создайте собственную конфигурацию для своей копии проекта; не публикуйте пароли
или ключи. Для обновления уже установленной сборки требуется исходный ключ.
Проверяемый публичный сертификат указан в [signing-certificate.json](signing-certificate.json).
Релиз остаётся `debuggable=false`.

## Пять вариантов APK

```bash
python3 scripts/build-release.py
./gradlew :app:lintDebug
```

Скрипт собирает ARM64, ARMv7, x86, x86_64 и universal; каждый APK проверяется
на пакет, версию, подпись, разрешения, ABI, ZIP alignment и побайтное совпадение
библиотек/ресурсов с libVLC 3.7.7. Результаты: игнорируемый `release/`, включая
`SHA256SUMS.txt` и `release-manifest.json`. Подробные отчёты: `qa/reports/release/`.

Для отдельной сборки:

```bash
./gradlew :app:assembleRelease -Pzem.abis=arm64-v8a
python3 scripts/audit-release.py --abis arm64-v8a --variant arm64-v8a
```

Версия задаётся только в `app/build.gradle`. Каждое завершённое изменение
повышает versionName на один шаг и Android versionCode. Обновляйте CHANGELOG; README не содержит номера текущей версии. libVLC закреплён на 3.7.7; [происхождение](libvlc-provenance.json).

## Проверки

```bash
bash scripts/core-checks.sh
# ffmpeg и Python Pillow нужны только для синтетических тестовых видео.
python3 qa/prepare-fixtures.py
python3 qa/device_simulator.py
```

В другом терминале запустите собственный тестовый эмулятор и проверки:

```bash
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest -Pzem.abis=x86_64
bash scripts/verify-emulator.sh
python3 qa/run-playback-audit.py
python3 qa/run-live-audit.py
python3 qa/run-format-audit.py
```

Скрипты обращаются только к `emulator-5586`; физические устройства не затрагиваются.
Сценарий `speed_only` проверяет локальное и Wi-Fi воспроизведение на 4×, затем
возврат к 1×. Сценарий `readme_only` сохраняет реальные скриншоты приложения.
Оба передаются через `adb shell am instrument -w -e <scenario> true`.

Тестовый адрес `10.0.2.2` разрешён только в debug. Синтетические медиа создаются
в `qa/generated/fixtures/`, результаты — в `qa/reports/`. Эти каталоги,
`release/`, `build/`, кэши, логи и временные `runs/` исключены из Git.

## Важные ограничения

Сетевые сокеты привязываются к захваченному Wi-Fi отдельно; весь процесс
никогда не привязывается к сети регистратора. Отложенные действия проверяют
исходный CTP-сеанс. Задняя камера включается пользователем в профиле устройства.
Общие команды удаления и сброса заблокированы; форматирование проходит только
по отдельному подтверждаемому пути с проверкой ответа `FORMAT.frm=1`.

В репозитории остаются актуальные исходники, тесты, скрипты, документация и
скриншоты. Старые APK, baselines и выведенные из использования эксперименты
не должны возвращаться в Git. Коммиты используют нейтральное имя проекта.

## Android 7

`desugar_jdk_libs_nio:2.1.5` переносит java.time, java.nio.file и используемые
современные Java API на API 24. Локальные записи на API 24–28 публикуются в
общую папку Download/Zem iBox Drive после запроса разрешения на файлы;
на API 29+ используется MediaStore.Downloads без такого разрешения.
Разрешения READ/WRITE_EXTERNAL_STORAGE ограничены maxSdkVersion 28.

Сценарий `android7_only` запускается на чистой установке эмулятора API 24:
он проверяет выключенную диагностику, запрос разрешения, сохранение оригинала,
лайв, кадр, запись со звуком, внутренний плеер и обновление списка после удаления.
Для скриншотов: `python3 qa/prepare-readme-fixture.py`, затем запуск симулятора
с `ZEM_README_FIXTURE=1` и сценарий `readme_only`. Изображение дороги создано
программно; это демонстрация интерфейса, не запись с физического устройства.

## Обновления приложения

Источник — последний опубликованный стабильный релиз GitHub. APK выбирается
по архитектуре телефона с резервным универсальным вариантом. Проверяются
ожидаемый размер, SHA-256 из метаданных GitHub, пакет, версия, минимальная ОС,
нативная архитектура и совпадение сертификата с установленным приложением.
Интернет-запросы не привязывают процесс к Wi-Fi регистратора.

Проверка выполняется не чаще раза в сутки при открытом приложении и вручную.
Скачивание требует нажатия. Большие APK загружаются четырьмя непересекающимися HTTP-диапазонами;
если сервер игнорирует Range, используется один полный ответ. Каждый диапазон
проверяется до записи, а общий SHA-256 — до проверки подписи и установки.
Отмена прерывает координирующий поток и закрывает все соединения, временный файл
каждой попытки изолирован от следующей. Диалог показывает скорость, объём и оценку времени.
Установка использует системное окно Android,
не начинается в фоне, во время сохранения видео или скачивания архива.
Разрешение неизвестных источников пользователь выдаёт в настройках Android.

Проверки `updates_only` используют локальный сервер с реальным APK приложения:
параллельная загрузка и её скорость на ограниченном соединении, резервный полный ответ,
неверные диапазоны, повреждённый хеш, обрыв, отмена зависшего чтения и немедленный повтор,
отказ сервера, неправильный
пакет/версия/сертификат, URI установщика и ограничение доступа к файлу.
Отдельно проверяется настоящий HTTPS API GitHub. `updates_ui_only` проверяет
видимость действий диалога при крупном шрифте. Системный установщик в тесте
перехватывается; запущенное приложение не заменяется.

Релиз сначала загружается как черновик со всеми APK и контрольными суммами,
а затем публикуется. Это не позволяет проверке обновлений увидеть неполный выпуск.

## Архив, загрузки и библиотека

`ArchiveScreen` отвечает за архивный экран, `ArchiveSelection` — за пересечение
временных промежутков с целыми роликами. Даты интерпретируются как локальное время
регистратора; окно включает пересекающиеся ролики, а не только начинающиеся внутри.
`PhoneLibraryScreen` управляет фильтрами и снимком локального списка, `MediaRows`
используется обоими экранами. `MainActivity` сохраняет маршрутизацию и связь с камерой.

`DownloadQueue` хранит задания в SQLite. Идентификатор учитывает устройство, поколение
карты, путь, время, размер и защищённость оригинала. Работающие задания после
перезапуска сервиса переходят на паузу. Возобновление требует исходного устройства
и карты; подключение к другой сети не перенаправляет очередь. `TransferService`
скачивает по одному оригиналу и сохраняет частичные копии; `DownloadsActivity`
управляет отдельными заданиями.

`StorageLocation` использует системный выбор документов и сохраняемые URI-разрешения.
По умолчанию остаётся MediaStore Downloads либо совместимый путь Android 7–9.
`MediaExports` создаёт отдельный MP4 без перекодирования совместимых дорожек; начало
сдвигается к предыдущему ключевому кадру. Исходник открыт только для чтения, временный
файл удаляется при ошибке или отмене. `PlaybackHistory` хранит позицию по источнику
и метаданным ролика.

`improvements_only` проверяет пересечение времён, постоянную очередь, паузу зависшего
HTTP, докачку, источник задания, отсутствие аудио, сохранность оригинала при экспорте,
дорожки фрагмента, реальный системный выбор папки, точный шаг и полноэкранный вывод.

### Покадровый просмотр и выбор файлов

Флаг инструментального запуска `player_tools_only=true` проверяет фактические
декодированные кадры, возврат вперёд/назад, настоящее долгое нажатие, отпускание
и отмену жеста, стабильность границ видео, чекбоксы и окно «О приложении».
Для этого нужен симулятор устройства из `qa/device_simulator.py` с обычными
тестовыми медиа и собственный эмулятор проекта. На Android 7 перед запуском
выдайте отладочной сборке разрешения чтения и записи общего хранилища.

Обычное воспроизведение использует libVLC. При точном шаге на паузе `FrameReader`
получает ближайший кадр через Android MediaMetadataRetriever в отдельном потоке;
на Android 7–8 используется MediaExtractor/MediaCodec с декодированием кадров
в порядке их показа, поскольку старый MediaMetadataRetriever тоже может
возвращать один кадр для соседних позиций;
это обходит сохранение предыдущего изображения при паузе на H.264 с B-кадрами.
Одновременно выполняется один запрос. Отпускание кнопки отменяет показ ещё
не готового кадра. При продолжении воспроизведения статичный кадр закрывается
после возобновления вывода libVLC. Размер области видео от этого не меняется.
